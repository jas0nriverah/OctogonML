# Manual release smoke check

Run these checks against the service after automated tests pass.

1. Install with `python -m pip install -c requirements-lock.txt -e '.[dev,postgres]'`, run `cagemetrics bootstrap`, then start `cagemetrics serve`. Bootstrap ingests/migrates without refitting the packaged model. Confirm `/health/live` and `/health/ready` return success and the expected database/model identity. After a new source snapshot is ingested, confirm the loaded service refuses stale-state inference with 503 until restarted.
2. Open `/`. Verify upcoming cards, event filters, athlete photos, and the initials fallback. Counts and ranges must match the API. Unresolved identities should show unavailable forecasts, and published times should identify card/segment starts.
3. In Matchup Lab, select two distinct athletes. Generate both three-round forecasts at line 50.5 and verify over+under≈1 with zero push. Generate five-round forecasts at line 50 and verify over+under+push≈1 and positive push probabilities. Confirm Gaethje/Pimblett photos load, mirrored rows share scales, negative net differentials retain their sign, and Last 5/All covered switches the observed sample. Inspect each prediction ID through `/docs`.
4. Open “Why this projection?” Confirm actual eligible history, comparison units, and the noncausal sensitivity note. Close/reopen without regenerating the forecast. In Fighters, check search, division filtering, pagination, individual profile links, direct-link reload, browser back/forward, last-five/all-covered history, linked opponents, and comparison prefills. Verify lesser-known fighters and a missing-photo fallback as well as featured names; directory coverage should remain 2,074 fighters.
5. Open Recent Results. Confirm the declared window, actual dates, 25 bouts/50 athlete outcomes, synthetic-line disclosure, errors, and reconstructed-after-event label.
6. Under Research → Model Evidence, verify the preserved V1 historical MAE 25.68 versus baseline 28.24 and the separate V3 artifact identity. The V3 study should show 2021–2023 selection, 2024 confirmation NLL 4.73010 versus 4.78220, bootstrap intervals, no established MAE gain, and the previously-seen-year caveat. Open the collapsed V2 study and confirm the richer-feature challenger was not promoted. `/api/v1/research` and `/api/v1/research/predictions.csv.gz` must return the preserved study and compressed rows. A retrospective comparison must not become a new holdout claim.
7. Under Research → Forward Tracker, distinguish a fresh empty local ledger from the preserved real issuance run. The original 118 V2 athlete forecasts remain immutable; any V3 issuance must have separate model/version lineage and prospective outcomes remain pending. Check the prior upcoming report archive before regenerating projections. Exercise JSON import/client validation without inventing a scheduled fight. Verify immutable provenance, idempotent retry, and CSV/JSON exports only on legitimate fixtures. Past timestamps and invalid IDs must be rejected by the backend.
8. At a 390×844 viewport, inspect navigation, fighter cards, charts, forecast inputs, long hashes, and table scrolling. The page should not overflow horizontally. Check keyboard focus and accessible labels.
9. Run the documented serial and concurrent benchmark commands against the same service/database. Preserve both reports. Review console/server errors and error rate; do not hide a slower concurrency result.
10. Run `ruff check src tests migrations scripts`, `pytest`, and `node --check src/cagemetrics/web/app.js`. PostgreSQL integration uses a dedicated `CAGEMETRICS_TEST_DATABASE_URL`. Check both the test and container jobs in the current CI run.
11. Confirm the default `auto` channel loads V3 when its verified artifact is available. Restart with `CAGEMETRICS_MODEL_CHANNEL=v2`, then `v1`, and verify explicit rollback identities. Restore `auto` and restart. Changing an artifact or channel requires a restart; a request must not silently retrain or rewrite earlier forecasts. Regenerate benchmarks for V3 rather than treating preserved V2 latency as current.

The forward ledger check must never be satisfied by inserting a fake completed example. If no real future fixture is verified, record validation/export checks and retain the empty ledger; leave prospective scoring unclaimed.
