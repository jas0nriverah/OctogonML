# Manual release smoke check

Run against the final service after automated tests. Record the actual loaded model versions and source hash; do not infer readiness from a screenshot or a generated file.

1. **Startup.** Install the constrained dependencies, run `cagemetrics bootstrap`, and start `cagemetrics serve`. Check `/health/live` and `/health/ready`. Bootstrap must migrate/import without model fitting. A changed SQL source snapshot must refuse stale loaded inference until restart.
2. **Upcoming cards.** Open `/`, filter events, and compare displayed counts/dates with `/api/v1/upcoming`. Unmatched identities remain unavailable. Times are card/segment starts. Confirm the visible research-only/not-betting-advice notice; no unsupported completed future outcomes should appear.
3. **Portraits and directory.** Search the 2,074-athlete directory, filter divisions, paginate, and open/reload an individual profile. Check back/forward navigation, opponent links, comparison prefills, last-five/all-covered samples, and initials fallbacks. Verify Adam Yandiev's full face remains visible, Joey Gomez never displays the removed Jose Quinonez alternate, and Borshchev/Gaethje/Pimblett load real photos. The current verified count is 2,036, not every canonical fighter.
4. **Scenario policy.** Select a known same/adjacent pair and forecast. Reverse the pair. Then try a distant division gap and a cross-category pair; browser and API must reject unrealistic scenarios before saving forecasts. Unknown division evidence must not be guessed. Class ceilings are not actual body weights.
5. **Winner.** Verify complementary probabilities, decisive-outcome scope, correct baseline/V2 identity, and a saved `/api/v1/winner-predictions/{id}` round trip. The winner channel defaults to gated V2 when available; the 2024 retrospective comparison is 63.91% accuracy, log loss 0.642838, Brier 0.225529. This is ML-only evidence, never an AI-guidance score. A missing winner model must leave strike forecasts usable.
6. **Elapsed time.** Generate three- and five-round duration forecasts. Check all half-round thresholds through the scheduled limit, finite nonincreasing survival, and over+under+push≈1. At the full-time line, over=0 and push equals scheduled-time completion. Exact integer boundaries can have push mass. Reverse-order duration forecasts must agree. Mean duration is within the clock; completion must not be labeled proof of a decision. Verify the saved rounds-family route and independent artifact identity.
7. **Strikes and comparisons.** Generate a half-point and an integer-line strike forecast for both athletes. Half-points have zero push; integer over+under+push≈1. Charts use consistent scales, retain negative net differential, show units/sample sizes, and do not turn strike totals into winner odds. Zero-history metrics remain unavailable.
8. **Rankings.** `/api/v1/rankings` and the display retain source/observed timestamps. The 206-entry media observation retains the yearless “Tuesday, Oct. 20” footer, explicitly inferred year 2026, null full published-board date, and actual October 22 availability timestamp. Current display facts remain separate from stale-masked model inputs; unavailable historical rank does not mean unranked.
9. **Optional AI analysis.** First verify the configured provider and model. Submit matching saved forecast IDs to `/api/v1/matchup-analysis`, not client-authored facts. On a successful real provider call, check exact sourced advantages/comparison, original fact IDs, eligible catalogue routes or explicit abstention, conditional tactical language, experimental labeling, a shift no larger than ±5 points, complementary adjusted probabilities, and the unchanged original ML forecast. GET/retry must return the same immutable saved analysis. A timeout/unavailable provider must show an error, not fake prose or a default probability. The basic JSON check passed in 10.7 seconds; complete catalogue-based analyses separately passed in both fighter orientations in 37.5 and 56.6 seconds with zero AI adjustment. Record fresh results for the deployed prompt/model; these examples do not prove every output semantically correct. Do not queue simultaneous local-model checks.
10. **Recent and research.** Recent Results must identify October 8–22, 25 bouts/50 outcomes, actual October 10/17 events, synthetic lines, and reconstructed-after-event status. Model Evidence separates V1 historical strike MAE, V3 distribution research, Winner V2, and duration evaluation. Previously seen 2024 results must not be labeled an untouched holdout. Duration nominal 80% coverage of 93.7% is conservative, not exact calibration.
11. **Forward ledger.** Distinguish an empty fresh database from preserved issued batches. V2/V3 forecasts keep separate versions; no settled prospective performance is claimed. Validate legitimate fixture import, pre-event clock rejection, atomic failure, idempotent retry, immutable provenance, and full CSV/JSON exports. Never insert a fake real-world fight to make the tracker look populated.
12. **Responsive/accessibility check.** At 390×844, inspect navigation, fighter images, comparison charts, inputs, long identifiers, loading/error states, and table scrolling. Avoid horizontal page overflow. Check keyboard focus and form labels.
13. **Automated verification.** Run `ruff check src tests migrations scripts`, `pytest`, and `node --check src/cagemetrics/web/app.js`. PostgreSQL checks use a dedicated `CAGEMETRICS_TEST_DATABASE_URL`. Inspect the current CI test/container jobs. Do not publish a stale test count as the final result.
14. **Rollback and performance.** Restart with explicit strike `v1`/`v2`/`v3` and winner `v1`/`v2` channels, check identities, then restore intended settings. No request may retrain or mutate an old forecast. Retained millisecond benchmarks cover strikes with SQL writes, not AI generation; regenerate serial/concurrent reports after runtime changes and preserve errors as well as latency.
